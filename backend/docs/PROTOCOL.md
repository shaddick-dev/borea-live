# Borea backend protocol

Generated by `borea-installd --protocol`.

JSON-RPC 2.0, one JSON object per line, at `/run/borea/installd.sock`. Socket mode 0660; peer UID must be root or the live `borea` user. Requests are limited to 1 MiB and idle connections to 30 seconds. At most 16 connections run concurrently.

| Method | Parameters | Result |
|---|---|---|
| `system.info` | none | version, UEFI, Secure Boot, firmware_setup restart capability, motion, power facts and low-battery warning |
| `system.methods` | none | this method registry |
| `hardware.get` | none | hardware report and automatic driver facts |
| `net.scan` | none | deduplicated SSIDs, security, strength, known/active |
| `net.connect` | ssid, hidden?, secret? | Connecting; poll net.status |
| `net.status` | none | NM connectivity and connection activation state |
| `geo.suggest` | none | country, time zone and locale/keyboard defaults, or null |
| `locale.languages` | none | all UTF-8 locales with native and English names |
| `locale.keyboards` | none | all XKB layouts and variants |
| `locale.timezones` | none | all compiled time zone identifiers |
| `catalog.get` | none | single catalog: all distros, sources, profiles, apps and desktops |
| `disks.list` | none | read-only disk/partition facts, NTFS safety flags and per-partition max_linux_size (bytes or null) |
| `plan.validate` | plan, step? | null or Hint; step accepts a partial draft |
| `plan.review` | plan | Review, layout, bootstrap, pinned external sources, approval digest, power facts and warning |
| `plan.render` | plan | review-only script and approval digest |
| `install.start` | plan, secrets, approval | job_id; revalidates approval and disk before writes |
| `install.events` | after? (absolute cursor, initially 0) | events (up to 256), cursor, more, truncated, busy, job_id |
| `install.subscribe` | after? | ack, then install.events notifications until worker ends |
| `install.retry` | action_id | null; only the current recoverable action is allowed |
| `install.log` | none | redacted install log |
| `system.reboot` | firmware_setup? (boolean, default false) | null; refuses while an installation is active; firmware setup requires supported UEFI |
| `handoff.review` | handoff (version, target, disk, extras) | Review of a hand-off to another installer (pinned release, disk changes, extras added on first start, what to choose in it) and approval digest |
| `handoff.start` | handoff, approval | job_id; downloads and verifies the installer onto the stick's data partition, applies only the reviewed disk changes, then kexecs into it. Events as install.events |

Errors use `{code:-32000,message,data:{field}}`; malformed JSON-RPC uses -32600. Never log request bodies containing secrets.

`Plan`, `Secrets`, `Step` and identity types are defined in `borea-core`; `Job` and its typed actions in `borea-job`; events and faults in `borea-exec`. Wire enum spellings follow their serde attributes. No distro, profile, app, disk or account is selected implicitly. A complete Plan is mandatory for Review, render and start. Partial validation checks only the requested step and never fills later choices. Passphrase confirmation belongs in the UI; the service validates actual secret lengths and administrator requirements.

Review pins native bootstrap checksums, repository keys, AUR snapshots and AppImage releases. Submit the returned approval digest with the identical Plan; changed upstream metadata requires another Review. Secrets are a separate object (`passphrase`, optional `admin` and `wifi`) and must be sent over the socket, never argv or a plan file.

Event cursors are absolute. The last 4096 events are retained; responses contain at most 256 events, and `more:true` requests another batch; `truncated:true` means older events were dropped and the client should offer the full log. Subscriptions receive batched `install.events` JSON-RPC notifications with the same result shape as polling. A disconnected subscriber does not cancel the worker. A retryable failure keeps the worker and private mounts alive for `install.retry`. Destructive actions cannot be retried automatically.

`plan.validate` step values: network, locale, distro, desktop, system, disk, you, review. Network takes `net`; locale takes `locale`; distro takes `distro` and `release`; desktop requires an explicit `desktop` key (null is no desktop); system takes distro, desktop, env, addons, picks, apps and sources; disk takes disk, distro and desktop; you takes user. Review validates the complete Plan.
